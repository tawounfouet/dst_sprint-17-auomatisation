# 191.07 — Retour d’expérience

Le principal saut pédagogique entre les labs et l’examen final est le passage d’un rôle WordPress monolithique à une architecture réellement distribuée : **un rôle par machine** et un flux réseau applicatif à prouver.

1. Un déploiement réussi sur chaque machine ne prouve pas l’intégration : il faut tester `web1 → db1:3306`.
2. L’inventaire porte la topologie et permet de dériver l’adresse DB via `hostvars`.
3. Le rôle MySQL doit être prêt avant l’installation PrestaShop ; l’ordre des plays est donc une décision d’architecture.
4. Vault protège les secrets dans le dépôt, pas automatiquement dans les logs ; les tâches sensibles utilisent `no_log`.
5. Le sujet conseille un compte `root` distant. L’implémentation de référence choisit un compte applicatif dédié et documente cet écart de durcissement.
6. Le ZIP doit être portable et ne contenir ni IP réelle, ni clé privée, ni `.vault_pass`.
