# 191.07 — Spécifications du projet final Ansible

## 1. Source du besoin

Le sujet demande :

- un rôle pour déployer **PrestaShop** ;
- un rôle pour déployer **MySQL** ;
- une communication fonctionnelle entre le serveur web et la base ;
- un playbook orchestrant les rôles ;
- des logs de tests ;
- des scripts fonctionnels ;
- un rendu ZIP.

Les ports cités dans le sujet sont **80/TCP** pour HTTP et **3306/TCP** pour MySQL.

## 2. Critères d’acceptation

| ID | Critère | Preuve attendue |
|---|---|---|
| EX-01 | Deux rôles distincts existent | arborescence `roles/prestashop` et `roles/mysql` |
| EX-02 | Le rôle MySQL installe et démarre MySQL | `systemctl is-active mysql` |
| EX-03 | Une base applicative existe | requête `SHOW DATABASES` |
| EX-04 | Un compte applicatif existe | connexion MySQL avec le compte applicatif |
| EX-05 | MySQL écoute sur une interface permettant le flux web→DB | `ss -ltnp` / connexion depuis web1 |
| EX-06 | Le rôle PrestaShop prépare Apache/PHP | services et modules présents |
| EX-07 | PrestaShop est déployé sous `/var/www/prestashop` | fichiers applicatifs présents |
| EX-08 | Le vhost HTTP écoute sur 80 | `apache2ctl -S` + `curl` |
| EX-09 | Le serveur web joint db1:3306 | test TCP et authentification SQL |
| EX-10 | Le playbook orchestre d’abord DB puis Web | `playbooks/site.yml` |
| EX-11 | Une seconde exécution est non destructive | comparaison des `changed=` |
| EX-12 | Les secrets ne sont pas commités en clair | Vault + `.gitignore` |
| EX-13 | Les logs sont capturés | `evidence/logs/*.txt` |
| EX-14 | Un ZIP propre peut être généré | `scripts/package_exam.sh` |

## 3. Hypothèses d’exécution

La solution cible des machines Debian/Ubuntu disposant :

- d’un accès SSH depuis le control node ;
- d’un utilisateur Ansible avec `sudo` ;
- d’un accès réseau web1 → db1 sur TCP/3306 ;
- d’un accès client → web1 sur TCP/80 si l’on souhaite tester depuis l’extérieur.

L’infrastructure peut être Multipass, une VM locale ou un cloud : l’inventaire est le point d’adaptation.
