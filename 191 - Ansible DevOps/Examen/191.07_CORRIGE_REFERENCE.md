# 191.07 — Corrigé de référence

> Ce document décrit une **solution de référence** pour satisfaire l’évaluation. Il ne constitue pas encore la preuve qu’une implémentation réelle a été exécutée. Cette preuve sera produite dans `Projet_Final/`.

## 1. Choix de solution

Deux voies sont admises par le support :

```text
A. Prestashop + MySQL   ← solution de référence de l’énoncé
B. alternative web + MySQL
```

Le corrigé de référence privilégie Prestashop afin de rester au plus près de l’énoncé.

## 3. Inventaire de référence

```yaml
all:
  children:
    web:
      hosts:
        web1:
    database:
      hosts:
        db1:
```

Les adresses et chemins propres à l’environnement restent dans des fichiers locaux ou `.example`.

## 4. Variables principales

Exemples non secrets :

```yaml
app_db_name: prestashop
app_db_user: prestashop_app
mysql_port: 3306
http_port: 80
```

Les secrets ne doivent pas être versionnés en clair. Le chapitre Vault fournit le mécanisme de chiffrement.

## 5. Rôle MySQL

Responsabilités :

```text
installer MySQL
      ↓
démarrer le service
      ↓
créer la base
      ↓
créer/configurer l’identité DB
      ↓
autoriser le flux requis depuis le serveur web
```

Le support suggère un utilisateur `root` pour permettre au serveur web de se connecter. Le corrigé de référence propose plutôt un utilisateur applicatif dédié afin de limiter les privilèges. Cet écart est une décision de durcissement explicite, pas une reformulation de l’énoncé.

## 6. Rôle Prestashop

Responsabilités :

```text
installer dépendances
      ↓
installer serveur HTTP/PHP requis
      ↓
récupérer/déployer Prestashop
      ↓
générer configuration
      ↓
connecter Prestashop à MySQL
      ↓
exposer HTTP :80
```

Les détails exacts de version et d’installation seront fixés lors du projet réellement implémenté.

## 7. Playbook principal

Structure de référence :

```yaml
---
- name: Configure database
  hosts: database
  become: true
  roles:
    - mysql

- name: Configure ecommerce web server
  hosts: web
  become: true
  roles:
    - prestashop
```

## 8. Validation de la communication

Le point clé de l’examen est :

```text
WEB ───────► MYSQL
     :3306
```

Une validation correcte ne se limite donc pas à vérifier que MySQL fonctionne sur `db1` : il faut tester la connexion **depuis `web1`**.

## 9. Gestion des secrets

Référence recommandée :

```text
group_vars/database/vault.yml
          │
          └── ansible-vault encrypt
```

Le mot de passe Vault reste hors Git.

Les tâches manipulant des mots de passe peuvent utiliser `no_log: true` lorsque leur sortie risquerait de révéler un secret.

Le corrigé est considéré complet lorsqu’il permet de produire :

