# 192.03 — Terraform : Variables, outputs et dépendances

> Sprint 17 — Automatisation  
> Module : Terraform DevOps  
> Durée indicative DataScientest : 1 h 30  
> Niveau : Normal

## 1. Objectifs pédagogiques

Ce chapitre rend les configurations Terraform **dynamiques, réutilisables et paramétrables** grâce aux variables d’entrée. Il introduit également les références entre ressources, les outputs et la gestion des dépendances.

À l’issue de ce chapitre, on doit être capable de :

- déclarer et typer des variables d’entrée ;
- utiliser `default`, `description`, `validation`, `sensitive` et `nullable` ;
- surcharger des valeurs via CLI, `.tfvars` et variables d’environnement ;
- référencer les attributs d’autres ressources ;
- créer des outputs ;
- comprendre les dépendances implicites et explicites ;
- structurer une configuration AWS plus dynamique.

---

## 2. Variables d’entrée

Les variables d’entrée permettent de rendre une configuration adaptable sans modifier le code de chaque ressource.

Exemple :

```hcl
variable "image_id" {
  type    = string
  default = "ami-064736ff8301af3ee"
}

variable "availability_zones" {
  type    = list(string)
  default = ["eu-west-3b"]
}
```

Une variable est référencée avec :

```hcl
var.nom_de_variable
```

Exemple :

```hcl
resource "aws_instance" "datascientest_instance" {
  ami           = var.image_id
  instance_type = "t3.micro"
}
```

---

## 3. Arguments des variables

Le support présente les arguments suivants :

- `default` ;
- `type` ;
- `description` ;
- `validation` ;
- `sensitive` ;
- `nullable`.

### 3.1 Valeur par défaut

```hcl
variable "instance_type" {
  type    = string
  default = "t3.micro"
}
```

### 3.2 Description

```hcl
variable "image_id" {
  type        = string
  description = "ID de l’AMI à utiliser pour le serveur"
  default     = "ami-03601e822a943105f"
}
```

### 3.3 Types

Types simples cités :

```text
string
number
bool
any
```

Collections utilisées dans le cours :

```hcl
list(string)
```

La bonne pratique consiste à typer explicitement les variables lorsque cela est possible.

---

## 4. Validation personnalisée

Terraform permet d’ajouter une règle de validation :

```hcl
variable "image_id" {
  type        = string
  description = "Identifiant de l’AMI à utiliser"

  validation {
    condition     = length(var.image_id) > 4 && substr(var.image_id, 0, 4) == "ami-"
    error_message = "La valeur de image_id doit commencer par 'ami-'."
  }
}
```

Cette validation permet de détecter une valeur incohérente avant le déploiement.

---

## 5. Variables sensibles

```hcl
variable "motdepasse" {
  type      = string
  sensitive = true
}
```

Une variable `sensitive` est masquée dans certaines sorties CLI.

> Point important du cours : `sensitive = true` ne chiffre pas la donnée dans le state. Une valeur sensible peut toujours être enregistrée en clair dans `terraform.tfstate`.

Il faut donc également sécuriser l’accès au state.

---

## 6. Valeurs nulles

```hcl
variable "variable_test" {
  type     = string
  nullable = false
}
```

Avec `nullable = false`, la valeur directe de la variable ne peut pas être `null`.

---

## 7. Méthodes d’affectation des valeurs

Le support présente plusieurs sources de valeurs.

### 7.1 Valeur `default`

```hcl
variable "type_instance" {
  type    = string
  default = "t3.micro"
}
```

### 7.2 Ligne de commande

```bash
terraform apply -var="image_id=ami-03601e822a943105f"
```

Exemple avec plusieurs variables :

```bash
terraform apply \
  -var='image_id_list=["ami-a","ami-b"]' \
  -var="instance_type=t3.micro"
```

### 7.3 Fichier `terraform.tfvars`

```hcl
type_instance = "t3.micro"
image_id      = "ami-03601e822a943105f"
monitoring    = true
```

Terraform charge automatiquement :

- `terraform.tfvars` ;
- `terraform.tfvars.json` ;
- `*.auto.tfvars` ;
- `*.auto.tfvars.json`.

### 7.4 Fichier explicite

```bash
terraform apply -var-file="valeurs.tfvars"
```

### 7.5 Variables d’environnement

Terraform recherche les variables préfixées par `TF_VAR_` :

```bash
export TF_VAR_image_id=ami-03601e822a943105f
terraform plan
```

## 8. Exemple complet de variables

```hcl
variable "type_instance" {
  type    = string
  default = "t3.micro"
}

variable "image_id" {
  type     = string
  nullable = false
}

variable "monitoring" {
  type    = bool
  default = false
}
```

Ressource :

```hcl
resource "aws_instance" "datascientest_instance" {
  ami           = var.image_id
  instance_type = var.type_instance
  monitoring    = var.monitoring

  tags = {
    Name = "datascientest"
  }
}
```

Validation :

```bash
terraform init
terraform validate
```

## 9. Références aux attributs de ressources

Terraform permet de relier les ressources grâce à leurs attributs.

Syntaxe générale :

```text
TYPE_DE_RESSOURCE.NOM_LOGIQUE.ATTRIBUT
```

Exemple :

```hcl
vpc_id = aws_vpc.datascientest_vpc.id
```

Exemple de groupe de sécurité :

```hcl
resource "aws_security_group" "datascientest_sg" {
  name        = "datascientest-sg"
  description = "Autorise HTTP, HTTPS et SSH"
  vpc_id      = aws_vpc.datascientest_vpc.id
}
```

Attachement à une interface réseau :

```hcl
resource "aws_network_interface_sg_attachment" "datascientest_sg_attachment" {
  security_group_id    = aws_security_group.datascientest_sg.id
  network_interface_id = aws_instance.datascientest_instance.primary_network_interface_id
}
```

Ces références permettent à Terraform de déduire automatiquement des dépendances.

## 10. Exemple EBS

Création d’un volume :

```hcl
resource "aws_ebs_volume" "datascientest_ebs" {
  availability_zone = var.availability_zone[0]
  size              = var.ebs_size

  tags = {
    Name = "datascientest-ebs"
  }
}
```

Attachement :

```hcl
resource "aws_volume_attachment" "datascientest_ebs_att" {
  device_name = "/dev/sdh"
  volume_id   = aws_ebs_volume.datascientest_ebs.id
  instance_id = aws_instance.datascientest_instance.id
}
```

Le support insiste sur une contrainte : l’instance EC2 et le volume EBS doivent se trouver dans la **même Availability Zone**.

## 11. VPC, subnet et interface réseau

Exemple de VPC :

```hcl
resource "aws_vpc" "datascientest_vpc" {
  cidr_block = var.cidr_block_vpc[0]

  tags = {
    Name = "datascientest_vpc"
  }
}
```

Sous-réseau :

```hcl
resource "aws_subnet" "datascientest_subnet" {
  vpc_id            = aws_vpc.datascientest_vpc.id
  cidr_block        = var.cidr_block_subnet[0]
  availability_zone = var.availability_zone[0]
}
```

Interface réseau :

```hcl
resource "aws_network_interface" "interface_reseau_instance" {
  subnet_id   = aws_subnet.datascientest_subnet.id
  private_ips = ["172.16.10.100"]
}
```

## 12. Outputs

Les outputs exposent certaines valeurs utiles après exécution.

Exemple :

```hcl
output "datascientest_instance_ip_public" {
  value = aws_instance.datascientest_instance.public_ip
}
```

Commande :

```bash
terraform output
```

### 12.1 Description

```hcl
output "instance_ip_addr" {
  value       = aws_instance.datascientest_instance.public_ip
  description = "Adresse IP publique de l’instance."
}
```

### 12.2 Output sensible

```hcl
output "secret_value" {
  value     = var.motdepasse
  sensitive = true
}
```

Comme pour les variables sensibles, cela masque l’affichage mais ne remplace pas une vraie stratégie de protection du state.

---

## 13. Dépendances implicites

Une référence à une ressource crée généralement une dépendance implicite.

Exemple :

```hcl
vpc_id = aws_vpc.datascientest_vpc.id
```

Terraform comprend ici que le VPC doit exister avant la ressource qui utilise son ID.

---

## 14. Dépendances explicites avec `depends_on`

Lorsque Terraform ne peut pas déduire une dépendance, on peut utiliser :

```hcl
depends_on = [
  aws_security_group.datascientest_sg
]
```

Le support recommande de réserver `depends_on` aux cas où la dépendance ne peut pas être exprimée naturellement par une référence.

---

## 16. Points clés à retenir

1. Les variables rendent le code Terraform configurable.
2. `type` et `validation` permettent de sécuriser les entrées.
3. `sensitive` masque l’affichage mais ne chiffre pas le state.
4. `.tfvars`, `-var`, `-var-file` et `TF_VAR_*` permettent de fournir des valeurs.
5. Les références aux attributs créent des relations entre ressources.
6. Les outputs exposent les informations utiles d’une configuration.
7. Terraform construit automatiquement un graphe de dépendances.
8. `depends_on` sert aux dépendances qui ne peuvent pas être déduites implicitement.
