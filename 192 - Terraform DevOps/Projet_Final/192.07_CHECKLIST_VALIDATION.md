# 192.07 — Checklist de validation

## Avant déploiement

- [ ] Terraform installé
- [ ] AWS CLI authentifiée
- [ ] aucune clé AWS présente dans le dépôt
- [ ] `terraform.tfvars` créé localement depuis l'exemple
- [ ] région = `eu-west-3`
- [ ] EC2 = `t3.micro`
- [ ] RDS = `db.t3.micro`
- [ ] EBS = 10 GiB

## Validation Terraform

- [ ] `terraform fmt -check -recursive`
- [ ] `terraform init`
- [ ] `terraform validate`
- [ ] `terraform plan`
- [ ] aucune ressource inattendue dans le plan

## Réseau

- [ ] VPC créé
- [ ] deux subnets publics
- [ ] deux subnets privés DB
- [ ] Internet Gateway présente
- [ ] route publique configurée
- [ ] HTTP 80 ouvert
- [ ] SSH fermé par défaut ou restreint à un CIDR explicite
- [ ] MySQL 3306 autorisé uniquement depuis le SG web

## EC2 / WordPress

- [ ] AMI récupérée dynamiquement
- [ ] instance `t3.micro`
- [ ] IP publique obtenue
- [ ] rôle IAM attaché
- [ ] Apache actif
- [ ] WordPress installé
- [ ] `wp-config.php` généré
- [ ] site accessible en HTTP

## RDS

- [ ] MySQL `db.t3.micro`
- [ ] RDS non public
- [ ] DB subnet group sur deux AZ
- [ ] Multi-AZ activé
- [ ] mot de passe géré par Secrets Manager
- [ ] connexion WordPress → RDS fonctionnelle

## EBS

- [ ] volume gp3 de 10 GiB
- [ ] volume chiffré
- [ ] même AZ que l'EC2
- [ ] volume attaché
- [ ] montage sur `wp-content/uploads`

## HTTPS bonus

Si activé :

- [ ] port 443 ouvert
- [ ] module SSL Apache actif
- [ ] certificat auto-signé généré
- [ ] site répond en HTTPS

## Nettoyage

- [ ] `terraform destroy` terminé sans erreur
- [ ] aucune ressource du projet ne subsiste
- [ ] aucun nettoyage manuel nécessaire
