# 192.07 — Corrigé du projet final Terraform

Ce document référence le corrigé **réellement implémenté** du projet final.

## Emplacement du code

```text
Projet_Final/wordpress-aws/
```

## Corrigé technique

La solution implémente les points suivants :

| Exigence | Réalisation |
|---|---|
| Région Paris | provider AWS paramétré par `region`, défaut `eu-west-3` |
| EC2 WordPress | module `ec2`, défaut `t3.micro` |
| AMI dynamique | data source Ubuntu officielle |
| AZ dynamiques | `aws_availability_zones` |
| RDS | module `rds`, MySQL `db.t3.micro` |
| Deux AZ DB | DB subnet group sur deux AZ + `multi_az = true` |
| EBS 10 GiB | module `ebs`, gp3 chiffré |
| Même AZ EC2/EBS | sortie `module.ec2.availability_zone` injectée dans `ebs` |
| HTTP | SG web TCP/80 |
| HTTPS bonus | option `enable_https` + certificat auto-signé |
| Modularisation | `networking`, `rds`, `ec2`, `ebs` |
| Secrets | mot de passe RDS géré par Secrets Manager |
| Déploiement WordPress | `user_data.sh.tftpl` |
| Nettoyage | `terraform destroy` |

## Workflow de correction

```bash
cd "192 - Terraform DevOps/Projet_Final/wordpress-aws"
cp terraform.tfvars.example terraform.tfvars
terraform fmt -recursive
terraform init
terraform validate
terraform plan
terraform apply
```

Tester ensuite l'URL retournée :

```bash
terraform output -raw wordpress_url
```

Puis nettoyer :

```bash
terraform destroy
```

## Important

Ce corrigé n'utilise pas les identifiants AWS présents dans les anciens supports pédagogiques. Aucune clé d'accès n'est versionnée. L'authentification AWS doit être fournie à Terraform par l'environnement d'exécution.
