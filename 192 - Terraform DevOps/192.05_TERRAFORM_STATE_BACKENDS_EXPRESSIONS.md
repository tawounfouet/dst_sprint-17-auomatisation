## 2. Le Terraform State

Terraform conserve une représentation de l’infrastructure gérée dans un **state**.

Par défaut, ce state est stocké localement dans :

```text
terraform.tfstate
```

Le state permet notamment de maintenir la correspondance entre :

```text
Configuration Terraform
        ↕
Terraform State
        ↕
Objets réellement présents chez le provider
```

Le support précise que le state est stocké au format JSON.

Des commandes comme :

```bash
terraform show
terraform output
```

s’appuient sur les informations du state.

---

## 3. Limites du state local

Le backend local convient à un travail individuel, mais devient problématique lorsque plusieurs personnes travaillent sur la même infrastructure.

Si chaque développeur possède son propre `terraform.tfstate`, les états peuvent diverger.

Dans un contexte collaboratif, l’objectif est donc de centraliser le state.

---

## 4. Backend local explicite

Terraform utilise un backend local par défaut. Il peut aussi être déclaré explicitement :

```hcl
terraform {
  backend "local" {
    path = "/home/ubuntu/datascientest-backend/terraform.tfstate"
  }

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}
```

---

## 5. Backend distant S3

Le support utilise un bucket S3 pour stocker le state à distance.

Création du bucket via AWS CLI :

```bash
aws s3 mb s3://mon-bucket-terraform-unique --region eu-west-3
```

Configuration Terraform :

```hcl
terraform {
  backend "s3" {
    bucket = "mon-bucket-terraform-unique"
    key    = "terraform.tfstate"
    region = "eu-west-3"
  }

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}
```

> Les clés AWS montrées dans le support d’origine ne sont volontairement pas reproduites. Les credentials doivent être fournis via un mécanisme sécurisé.

---

## 6. Migrer un state

Lors du passage d’un backend local vers un backend distant :

```bash
terraform init -migrate-state
```

Puis :

```bash
terraform apply -auto-approve
```

L’objectif est que le state soit désormais stocké à distance.

---

## 7. Verrouillage du state

Le cours insiste sur le fait que Terraform protège le state contre des accès simultanés pendant certaines opérations.

L’idée à retenir :

```text
Un state partagé
      ↓
Doit être cohérent
      ↓
Éviter les modifications concurrentes
```

La gestion du state est donc un sujet central pour le travail en équipe.

## 8. Expressions et boucles

Le support introduit plusieurs mécanismes :

- `count` ;
- `for_each` ;
- `for`.

Le chapitre se concentre principalement sur `count` et les conditions.

---

## 9. Utiliser `count`

Exemple : créer trois instances EC2 :

```hcl
resource "aws_instance" "datascientest_instance" {
  ami           = var.image_id
  instance_type = var.type_instance
  count         = 3
  monitoring    = var.monitoring

  tags = {
    Name = "datascientest"
  }
}
```

Le problème : les trois instances portent le même tag `Name`.

On peut utiliser `count.index` :

```hcl
resource "aws_instance" "datascientest_instance" {
  ami           = var.image_id
  instance_type = var.type_instance
  count         = 3
  monitoring    = var.monitoring

  tags = {
    Name = "datascientest-${count.index}"
  }
}
```

---

## 10. Effet de `count` sur les références

Dès qu’une ressource utilise `count`, Terraform la traite comme une **collection indexée**.

Avant :

```hcl
aws_instance.datascientest_instance.public_ip
```

Après `count = 3` :

```hcl
aws_instance.datascientest_instance[0].public_ip
aws_instance.datascientest_instance[1].public_ip
aws_instance.datascientest_instance[2].public_ip
```

Le support insiste sur cette idée :

```text
Sans count
    ↓
Ressource singulière

Avec count
    ↓
Collection de ressources
```

Une référence qui reste au singulier provoque des erreurs du type :

```text
Missing resource instance key
```

---

## 11. Outputs avec plusieurs instances

Une fois `count` utilisé, un output doit prendre en compte la collection.

Exemple pédagogique :

```hcl
output "datascientest_instance_ip_public" {
  value = aws_instance.datascientest_instance[*].public_ip
}
```

L’idée est de retourner les IP publiques de toutes les instances.

---

## 12. Fonction `length()`

La fonction `length()` retourne la taille d’une collection.

Exemple :

```hcl
count = length(aws_instance.datascientest_instance)
```

Le support l’utilise pour créer autant de volumes EBS que d’instances.

```hcl
resource "aws_ebs_volume" "datascientest_ebs" {
  count             = length(aws_instance.datascientest_instance)
  availability_zone = var.availability_zone[0]
  size              = var.ebs_size
}
```

Puis :

```hcl
resource "aws_volume_attachment" "datascientest_ebs_att" {
  count = length(aws_instance.datascientest_instance)

  device_name = "/dev/sdh"
  volume_id   = aws_ebs_volume.datascientest_ebs[count.index].id
  instance_id = aws_instance.datascientest_instance[count.index].id
}
```

---

## 13. Attacher un Security Group à plusieurs instances

Même logique :

```hcl
resource "aws_network_interface_sg_attachment" "datascientest_sg_attachment" {
  count = length(aws_instance.datascientest_instance)

  security_group_id = aws_security_group.datascientest_sg.id
  network_interface_id = aws_instance.datascientest_instance[count.index].primary_network_interface_id
}
```

On obtient alors une correspondance index par index.

---

## 14. Syntaxe de référence avec `count`

À retenir :

```text
PROVIDER_TYPE.NOM[INDEX].ATTRIBUT
```

Exemple :

```hcl
aws_instance.datascientest_instance[count.index].id
```

---

## 15. Conditions avec Terraform

Terraform n’utilise pas un `if` classique comme un langage impératif.

Le support introduit la syntaxe ternaire :

```text
CONDITION ? VALEUR_SI_VRAI : VALEUR_SI_FAUX
```

Exemple :

```hcl
count = var.environment == "dev" ? 1 : 3
```

Interprétation :

```text
environment == dev
        ↓ oui
1 instance

        ↓ non
3 instances
```

---

## 16. Exemple de variable d’environnement logique

```hcl
variable "environment" {
  type    = string
  default = "dev"
}
```

Puis :

```hcl
resource "aws_instance" "datascientest_instance" {
  ami           = var.image_id
  instance_type = var.type_instance
  count         = var.environment == "dev" ? 1 : 3

  tags = {
    Name = "datascientest-${count.index}"
  }
}
```

## 19. Points clés à retenir

1. `terraform.tfstate` maintient la représentation de l’infrastructure gérée.
2. Un backend distant facilite le travail collaboratif.
3. S3 peut être utilisé pour stocker le state à distance.
4. `terraform init -migrate-state` permet de migrer l’état lors d’un changement de backend.
5. `count` transforme une ressource singulière en collection indexée.
6. `count.index` permet d’identifier l’instance courante.
7. `length()` permet d’adapter dynamiquement le nombre de ressources.
8. Les expressions ternaires permettent d’introduire des conditions simples.
9. Les références doivent être adaptées dès qu’une ressource devient une collection.
